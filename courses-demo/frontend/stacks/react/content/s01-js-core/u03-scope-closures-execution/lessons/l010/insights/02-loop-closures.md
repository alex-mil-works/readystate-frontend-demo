# Классическая ловушка: `var` в цикле

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// 3, 3, 3
```

Почему не `0, 1, 2`? Потому что `var i` — одна переменная на всю функцию. Три замыкания ссылаются на **один и тот же** binding `i`. К моменту выполнения `setTimeout` цикл завершён, `i === 3`.

## Решение 1: `let` (ES2015)

```js
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// 0, 1, 2
```

`let` в `for` создаёт **новый binding** `i` для каждой итерации. Каждое замыкание захватывает свой экземпляр.

## Решение 2: IIFE (до ES2015)

```js
for (var i = 0; i < 3; i++) {
  (function (j) {
    setTimeout(() => console.log(j), 0);
  })(i);
}
// 0, 1, 2
```

IIFE создаёт новый scope с параметром `j`, который копирует текущее значение `i`.

## Почему это важно

Эта ловушка — один из самых частых вопросов на собеседовании по JavaScript. В продуктовом коде: `let` в циклах, `const` когда переменная цикла не меняется (например, `for...of`). `var` в цикле — антипаттерн.
